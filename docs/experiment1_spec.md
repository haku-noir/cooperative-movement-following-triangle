# 実験1 実装仕様書：三角形提示による視野共有追従システム

作成日：2026-09-15
対象プラットフォーム：Meta Quest 3 / Unity
本書は実装者（Claude Code）への仕様提示を目的とする。研究上の背景は、実装判断に必要な範囲のみ記載する。

---

## 0. 実装者への前提共有

### 0.1 このシステムが何を測るか

被験者 B が、**事前に録画された別人 A の身体運動に追従する**課題を行い、その追従精度を測定する。

追従対象は「A の首・左手・右手の3頂点が作る三角形」である。B は自分の同じ3頂点が作る三角形を、空間内に表示された A の三角形に一致させようとする。

### 0.2 検証したいこと

3頂点を「別々の点」として提示するより、「一つの三角形」として提示するほうが追従精度が高いか。そのために以下3条件を比較する。

| 条件 | 表示 | 教示 |
|---|---|---|
| C1 | 頂点のみ（球3個） | 「3つの点を合わせてください」 |
| C2 | 頂点のみ（球3個） | 「3つの点を三角形と見なし、その三角形を合わせてください」 |
| C3 | 頂点＋辺（三角形） | 「三角形を合わせてください」 |

- C1 → C2 の差 = 教示（認知的枠組み）の効果
- C2 → C3 の差 = 辺の描画（知覚的統合）の効果

**実装上重要**：C1・C2 は表示が完全に同一でなければならない。差異は教示テキストのみ。

### 0.3 スコープ外（実装しないこと）

以下は実験2の要因であり、**本実装には含めない**。ただしパラメータとしてインスペクタに公開し、後から変更可能にしておくこと。

- 頂点オフセット量 `d` の変動（実験1では固定値）
- 三角形の塗りつぶし（半透明面）表示
- 自己と相手の色差表示
- 双方向リアルタイム通信（実験1は録画再生の一方向のみ）
- パススルー映像の使用（実験1は完全な VR 空間内）

## 1. 技術要件

- Unity 6000.0 LTS または 2022.3 LTS
- Meta XR All-in-One SDK（`com.meta.xr.sdk.all`）
- XR Plugin Management：OpenXR、Meta Quest feature group を有効化
- ハンドトラッキング：`OVRManager > Hand Tracking Support = Controllers And Hands`
- 表示リフレッシュレート：`OVRManager.display.displayFrequency = 90` に固定（起動時に設定し、実際に適用されたかを検証してログに残す）
- トラッキング原点：`Floor Level`
- **試行中の再センタリングを禁止**する。`OVRManager.display.RecenteredPose` イベントを購読し、発生した場合はログに記録したうえで当該試行を無効フラグ付きで保存すること

## 2. 座標系と頂点定義

### 2.1 座標系

すべて **world 座標系（重力固定・床原点）** で扱う。

### 2.2 頂点の定義

3頂点は以下で生成する。

| 頂点 | 定義 |
|---|---|
| V0（首） | `CenterEyeAnchor.position + d * Vector3.down` |
| V1（左手） | 左手の手首またはMCPの world 座標 |
| V2（右手） | 右手の手首またはMCPの world 座標 |

**V0 の重要な仕様**：オフセット `d` は **重力方向（`Vector3.down`）に固定**する。頭部の回転に追従させてはならない。頭部座標系のローカル down を使うと頭部回転が頂点変位として混入し、実験の統制が崩れる。

- `d` はインスペクタ公開の float。デフォルト値 `0.15`（単位 m）。**パイロットで確定するまで暫定値**
- `d` は被験者の眼高で正規化した値 `d / h` もログに記録する（`h` はキャリブレーション時に計測した床から `CenterEyeAnchor` までの高さ）

### 2.3 手の頂点

`OVRSkeleton.Bones` から取得する。以下2候補を切替可能にし、デフォルトは中指MCPとする（指の開閉で頂点が動きにくいため）。

- `OVRSkeleton.BoneId.Hand_WristRoot`
- `OVRSkeleton.BoneId.Hand_Middle1`（中指MCP）

## 3. アプリケーション構成

単一 Unity プロジェクト内に2モードを実装する。起動時のメニューで選択する。

### 3.1 記録モード（Recorder）— 刺激作成用

演者 A の運動を記録する。

- 毎フレーム、以下を記録：タイムスタンプ、`CenterEyeAnchor` の position / rotation、両手の頂点 world 座標、両手のトラッキング状態と信頼度
- タイムスタンプは `OVRPlugin.GetTimeInSeconds()` を使用
- 記録開始前にキャリブレーション（§5.1）を実施し、A の体格情報をファイルに含める
- 保存先：`Application.persistentDataPath/recordings/`
- 形式：JSON（可読性優先。1ファイル1録画）

### 3.2 実験モード（Experiment）— 本番

被験者 B が追従課題を行う。

- 録画ファイルを読み込み、A の三角形を再生・提示
- B 自身の三角形をリアルタイムに生成・提示
- 誤差を毎フレーム算出しログに記録

## 4. 提示仕様

### 4.1 自己三角形（B 自身）

- 常時表示
- B の首頂点から左右の手頂点へ向かう構造
- **条件 C1・C2 では頂点の球のみ**、C3 では球＋辺を描画する
- 頂点球：直径 0.03 m、単色

### 4.2 相手三角形（A・録画）

- world 空間に表示
- **条件 C1・C2 では頂点の球のみ**、C3 では球＋辺を描画する
- 頂点球のサイズ・色・シェーダは自己三角形と完全に同一にする（実験1では自他同色。色差は実験2の要因）

### 4.3 辺の描画（C3 のみ）

- `LineRenderer` または専用メッシュ。線幅 0.01 m、自他同一
- 辺は自己三角形・相手三角形の両方に描画する（自他非対称にしてはならない）

### 4.4 背景（地）

B が自身の頭部運動を知覚するために**背景は必須**である。無地空間にしてはならない。

- テクスチャ付きの静止した部屋：床にグリッドパターン、壁に規則的な模様
- 部屋は試行中に一切動かない
- 照明は均一。影による追加手がかりを避けるため、リアルタイム影は無効

## 5. 試行フロー

### 5.1 キャリブレーション（各被験者の開始時に1回）

1. 床から `CenterEyeAnchor` までの高さ `h` を計測
2. 基準姿勢（両手を前方に開いて静止）を3秒保持させ、その間の平均から以下を算出
   - 首頂点から各手頂点までの距離（体格指標 `L_left`, `L_right`）
3. 結果を被験者プロファイルとして保存

### 5.2 体格正規化

A の三角形を B の体格に合わせてスケーリングする。

- スケール係数 `s = (B の L 平均) / (A の L 平均)`
- A の頂点を、A の首頂点を中心として `s` 倍する
- **これを実行時のスケール自由度として残してはならない**。キャリブレーション時に決定した固定値として適用する

### 5.3 位置合わせ（Registration）

各試行の開始時に実施する。

1. B に基準姿勢を取らせ、3秒静止
2. その間の B の三角形の平均と、録画の初期フレームの A の三角形が重なるよう、A の三角形全体に剛体変換を適用
3. **変換は平行移動とヨー回転のみ**とする。重力方向は共有されているため、ピッチ・ロール方向の回転は適用しない

### 5.4 1試行の構成

| フェーズ | 時間 | 内容 |
|---|---|---|
| 教示表示 | 被験者ペース | 条件に応じた教示文を表示 |
| 基準姿勢 | 3 s | Registration 実施 |
| 導入 | 10 s | 追従開始。解析から除外 |
| 区間1（複合） | 20 s | A が頭部並進と手を同時に動かす |
| 区間2（並進のみ） | 20 s | A が手を静止させ身体だけ並進させる |
| 区間3（手のみ） | 20 s | A が頭部を静止させ手だけ動かす |
| 区間4（複合） | 20 s | 区間1と同種 |

合計 93 s。区間境界のタイムスタンプは録画ファイルにメタデータとして持たせ、実験モードでログにマーカーとして書き出す。

**区間構成は録画側の演技で作る**ため、記録モードに区間マーカーを打つ機能（コントローラボタンまたは時間ベースのガイド表示）を実装すること。

### 5.5 条件と刺激の割付

- 3条件 × 3録画刺激
- ラテン方格により、条件順序と条件-刺激対応の両方をカウンターバランス
- 被験者IDを入力すると割付順が決定される仕組みにする

## 6. 誤差算出とログ

### 6.1 毎フレーム算出する量

すべて **B の三角形の代表寸法（首-手距離の平均）で正規化**した無次元量として記録する。絶対値も併記する。

1. **頂点距離**：`|V0_B - V0_A|`, `|V1_B - V1_A|`, `|V2_B - V2_A|` および総和
2. **Procrustes 分解**（スケール固定、平行移動と回転のみ推定）
   - 剛体成分：平行移動量、回転角
   - 形状残差：剛体変換後の頂点距離の残差
3. **頭部方向残差**：A と B の `CenterEyeAnchor` の前方ベクトルのなす角。※これは課題外の事後評価用
4. **三角形の面積と最小内角**：退化検出用
5. **ハンドトラッキング状態**：`IsTracked`、`HandConfidence`（左右別）

### 6.2 CSV ログ仕様

1試行1ファイル。ヘッダ行に被験者ID・条件・刺激ID・`d`・`d/h`・スケール係数・SDKバージョン・実効リフレッシュレートをコメント行として記載。

列：

```
t, phase_marker,
headA_px, headA_py, headA_pz, headA_qx, headA_qy, headA_qz, headA_qw,
headB_px, headB_py, headB_pz, headB_qx, headB_qy, headB_qz, headB_qw,
V0A_x, V0A_y, V0A_z, V1A_x, V1A_y, V1A_z, V2A_x, V2A_y, V2A_z,
V0B_x, V0B_y, V0B_z, V1B_x, V1B_y, V1B_z, V2B_x, V2B_y, V2B_z,
dist_V0, dist_V1, dist_V2, dist_sum, dist_sum_norm,
proc_trans, proc_rot_deg, proc_residual, proc_residual_norm,
head_dir_residual_deg,
tri_area_B, tri_min_angle_B,
hand_L_tracked, hand_L_conf, hand_R_tracked, hand_R_conf,
recenter_flag
```

### 6.3 解析はアプリ内で行わない

一致判定の閾値処理、継続長分布、破綻回数、復帰時間の算出は**すべて後処理（Python 等）で行う**。アプリは生ログの出力までを担当する。閾値を複数試す必要があるため、アプリ内で二値化してはならない。

## 7. 実装上の注意点

### 7.1 ハンドトラッキングの信頼性

Quest 3 のハンドトラッキングはカメラ視野外で外挿を行う。`IsTracked` と `HandConfidence` を必ず毎フレーム記録し、低信頼区間を後処理で除外できるようにする。

**実験を破綻させうる制約**：B が頭部を大きく動かすと手がカメラ視野外に出る。これにより検証可能な運動振幅が物理的に制限される。録画刺激の振幅はパイロットで安全範囲を確定する必要がある（§9）。

### 7.2 三角形の退化

両手と首頂点が一直線に近づくと、Procrustes の回転成分が不定になる。最小内角を毎フレーム記録し、閾値（例：10度）を下回った区間を後処理で識別できるようにする。実行時に警告表示は不要（被験者への干渉になるため）。

### 7.3 タイミング

- 録画の再生はフレーム番号ではなく**タイムスタンプ基準**で行い、フレーム間は線形補間（位置）・Slerp（回転）で補間する
- 実効フレームレートの変動をログに残す

### 7.4 教示文

C1・C2 の差は教示文のみである。教示文は外部テキストファイル（JSON）に分離し、コードに埋め込まない。実験者が文言を調整できるようにする。

## 8. エディタ上での検証手段（必須）

実装者は実機で動作確認できないため、以下を必ず実装すること。

1. **モック再生モード**：HMD 接続なしで、Unity エディタ上で録画ファイルを再生し、2つの三角形を描画できること
2. **合成録画生成機能**：既知の正弦波運動から録画ファイルを生成する機能。これにより、誤差算出が正しいかを解析的に検証できる
3. **誤差算出の単体テスト**：既知の変位（例：B の三角形を A から x 方向に 0.1 m ずらした状態）に対して、頂点距離・Procrustes 成分が期待値を返すことのテスト

## 9. パイロットで確定する事項（実装時は暫定値でよい）

以下は実装をブロックしない。インスペクタ公開の設定値とし、後から変更可能にすること。

- `d` のベースライン値（暫定 0.15 m）
- 録画刺激の運動振幅・周波数（破綻せず、かつ手がトラッキング視野に留まる範囲）
- 区間長（暫定 20 s）
- 頂点球の直径、辺の線幅

---

## 10. 未確定事項（実装者は勝手に決めず質問すること）

実装中に以下の判断が必要になった場合、推測で進めず確認を求めること。

1. 頂点球の色と形状が、背景に対して十分な視認性を持つか（背景テクスチャとの干渉）
2. 自己三角形と相手三角形が重なった際の描画順序（深度テストの扱い）
3. 被験者への進行状況フィードバック（残り時間表示など）を出すか否か。出すと課題への注意配分に影響しうるため、デフォルトは非表示とする
4. 教示表示を HMD 内で行うか、装着前に口頭で行うか
